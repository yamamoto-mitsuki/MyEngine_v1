## 0. 結論（先に）

1. **順番：ゲームの中身を決める → エンジンの足りない物をまとめて足す（1週目）→ あとはゲームだけ。**
   - エンジンに足りない物（スプライト・地面で止まる・空を消す）は、**どの案でも要る**。ゲームを先に始めると、穴に当たるたびにゲーム側に仮の物を書いて、後で捨てることになる。
   - 逆に、中身が決まらないうちにエンジンを作り込むと、使わない物に時間を使う。なので「中身を決める」が一番先（今日〜数日）。中身が決まるまでの間に、20章のパート K（小さな直し）を写しておくとよい。
2. **作り方は 2.5D**：3D の空間に「絵を貼った板」を並べて、横からカメラで撮る。**今のポイントライト・Bloom・Collider・Scene ビューがそのまま使える**（2章）。
3. **エンジンに足す物は5つ**（5章）。最小なら E1・E2・E4 の3つ。

   | | 足す物 | なぜ要るか |
   |---|---|---|
   | E1 | **Sprite Renderer**（画像の板・左右反転・コマ送りアニメ） | キャラ・地面・背景を絵で出す |
   | E2 | **Body 2D**（重力・地面と壁で止まる・接地の判定） | 今の Collider は「重なった」を知らせるだけで、止めてくれない |
   | E3 | **移動ギズモ**（Scene ビューで矢印を掴んで動かす・マス目に吸い付く） | ステージを作るのに、今は Inspector の数字を打つしかない |
   | E4 | **シーンの設定：空を消す**（SF4 の一部） | 何もしないと、エンジンの明るい空が後ろに出る |
   | E5 | **UI Image**（画面に貼る絵）＋**フェード付きの `LoadScene`**（SF3 の一部） | タイトル・クリア画面・切り替えの暗転 |

4. **中身の案は A「灯（ともしび）」がおすすめ**（3章）：プレイヤーの持っている火の明るさが体力。突進で敵を倒すと火が戻る。灯籠に火をつけながら奥へ進む。「暗い世界＋ライト」がそのまま遊びになり、体力のゲージを作らなくてよい。

## 2. 作り方：2.5D（3D の空間に板を並べて、横から撮る）

```
 上から見た図（右が +Z＝奥。カメラは +Z を向いている）

   [カメラ]            (ライト)   |遊ぶ面        |奥の背景        |もっと奥
   z = -20             z = -1.5   |z = 0         |z = +8          |z = +25
      ---------------------->     |Player        |柱・木          |山・空の板
                                  |地面・敵      |(ゆっくり動く)  |(もっとゆっくり)
```

**なぜ 2.5D か**

- ライト・Bloom・Collider・エディタの Scene ビュー・Play / Stop が、**全部そのまま使える**。「暗い世界にライト」は、今のエンジンの一番得意なところ。
- カメラがパース（今の Camera Component）なら、**奥に置いた板は自動でゆっくり動く**（多重スクロールをコードで書かなくてよい）。
- 2D 専用の仕組み（正投影のカメラ・2D のライト）を作らなくてよい。

**決まり（最初に決めておくと、後で直さなくて済む）**

| 決まり | 値 | 理由 |
|---|---|---|
| 遊ぶ面 | **z = 0**（プレイヤー・地面・敵・アイテム） | 押し戻し（E2）は x と y だけで考える |
| 1 ユニット | **1 マス ＝ 画像の 64 ピクセル** | Sprite Renderer の「1 ユニットあたりのピクセル数」を 64 に。プレイヤーの絵が 64×96 なら 1×1.5 ユニット |
| カメラ | z = -20 前後、縦の視野角 30〜35 度 | 画面の横に 20 マスくらい見える。望遠寄りにすると奥の板のゆがみが少ない |
| ライトの置き場所 | **z = -1〜-2（遊ぶ面より少し手前）** | Lambert は「板の向き」と「ライトの向き」の角度で明るさが決まる。ライトを板と同じ z に置くと真横から当たって暗くなる |
| 光っている物（灯籠の火・敵の目） | Shading を Unlit にした明るい絵を重ねる（加算） | ライトそのものは目に見えない。Unlit の明るい所に Bloom が掛かって光って見える |
| 真っ暗な所 | 平行光源を消す（または強さ 0.05 くらい） | 新しいシーンには平行光源が入っている。消すとライトの無い所は真っ黒 |

**絵について**

- **シルエット（黒い形＋光る目）**にすると、描く量がとても減り、「暗い世界」とも合う（背景は少しだけ明るく、キャラは黒い影として見える）。
- ドット絵は、今のテクスチャの読み方（ぼかして拡大する）だとにじむ。ドット絵にしたいなら E1 に「ぼかさない」を足すので、7章で教えてほしい。
- 素材サイトの絵を使うなら、規約（クレジットの書き方）を最初に確認して、`resources/` に `CREDITS.txt` を置いておく（8章）。

## 3. ゲームの中身の案

どれも「プレイヤーはジャンプと突進」「暗い世界にライト」を守っている。**遊びの中心に光を置く**のがポイント（光が飾りだけだと、世界観が画面にしか出ない）。

| | 案 A「灯（ともしび）」（おすすめ） | 案 B「光渡り」 | 案 C「灯を灯す狩り」 |
|---|---|---|---|
| ひとこと | 持っている火＝体力。敵を倒して火を保ちながら奥へ | 光の玉に突進すると空中でもう一度突進できる。玉をつないで闇を渡る | 敵は暗いと見えない。灯籠に火をつけると見えて倒せる |
| 光の役目 | 体力・見える範囲・やり直し地点 | 足場（道） | 敵を見つける・弱らせる |
| 突進の役目 | 攻撃＋火を取り戻す手段 | 移動（空中で伸ばす） | 攻撃 |
| 作る物 | プレイヤー・敵2種・光のかけら・灯籠・ゴール | プレイヤー・光の玉・敵1種・ゴール | プレイヤー・敵2種・灯籠・ボス |
| 良いところ | 体力のゲージ（UI）が要らない。緊張感（火が小さくなる）が作りやすい | 突進が気持ちいい | 世界観が一番強い |
| 心配なところ | 火の減る速さの調整 | 「届く・届かない」の調整に時間がかかる | ボスは時間がかかる。見えない敵はイライラしやすい |
| 20 時間に入るか | ○ | △（ステージの調整次第） | △（ボスを削れば ○） |

### 案 A「灯（ともしび）」の中身

- プレイヤーは小さな火を持っている（プレイヤーの子にポイントライト）。**火の明るさ（届く距離）＝体力**。
  - 何もしなくても少しずつ小さくなる（例：1 秒に 1%）。敵に当たると大きく減る（例：20%）。0 で火が消えてゲームオーバー（画面が暗くなる）。
- **敵（影）を突進で倒すと「光のかけら」を落とす**。拾うと火が戻る（例：10%）。
  - 突進が「攻撃」と「回復の手段」の両方になる → 突進を使う理由がある。
  - 突進を敵に当てると、空中でももう一度突進できる（連続で倒すと気持ちいい）。
- **灯籠（ランタン）**：触れると火がつき、周りが明るくなる。**やり直す場所**になり、火も満タンに戻る。
- **最後の大きな灯籠**に火をつけたらクリア。
- 敵は2種：**歩く影**（地面を往復。落ちない）・**飛ぶ影**（ふわふわ上下。近づくとゆっくり寄ってくる）。
- 画面：タイトル（ロゴの絵＋「Press Space」の絵）→ ステージ1つ（2〜3 分）→ クリア／ゲームオーバー（絵1枚）→ タイトルへ。
- 時間が余ったら：案 B の「光の玉」を足す（突進で当たると空中突進が戻る）・敵の3種目・2面目。

## 4. 手触りの最初の値（ジャンプ・突進）

アクションの手触りは、**数字をいじって何度も試す**ところ。全部 Settings ウィンドウ（`GlobalVariables` の Project に "Player" グループ）に出して、**ビルドし直さずに Play 中に変えられる**ようにする。最初の値は、よくある横スクロールのくらい（プレイヤーの高さ 1.5 ユニット）。

| 項目 | 最初の値 | メモ |
|---|---|---|
| 走る速さ | 7 ユニット/秒 | 0.1 秒で最高速、0.08 秒で止まる（少しだけ滑る） |
| ジャンプの高さ | 3.5 ユニット（約 2.3 マス） | 上がる時間 0.35 秒 → 初速 20、重力 57 |
| 落ちるときの重力 | 上がるときの 1.6 倍 | ふわっとしない。落ちる速さの上限 20 |
| 小ジャンプ | ボタンを早く離したら、上がる速さを半分に | ボタンの長さで高さが変わる |
| コヨーテタイム | 0.08 秒 | 足場の端から落ちた直後でも跳べる（「押したのに跳ばない」を無くす） |
| 先行入力 | 0.1 秒 | 着地の少し前に押したジャンプも効く |
| 突進 | 0.18 秒で 4.5 ユニット（速さ 25） | 突進中は重力なし・無敵。終わったら走る速さまで落とす |
| 突進の回数 | 空中で1回（着地か、敵に当てると戻る） | 地上では 0.3 秒あける |
| 敵に当てた | ヒットストップ 0.06 秒・画面を 0.1 秒揺らす | `Time::SetTimeScale(0)` で止めて、実時間で数えて戻す |
| ダメージ | 火が 20% 減る・後ろに飛ばされる・1 秒無敵（点滅） | |

- ジャンプの高さ・時間から初速と重力を決める式：初速 = 2×高さ÷時間、重力 = 2×高さ÷時間²（高さ 3.5・時間 0.35 → 20 と 57）。「高さ」と「時間」で調整すると、思った通りに変えやすい。

## 5. エンジンに足す物（設計のあらまし。コードは7章の答えの後）

大きさは「写す量」の目安（小：100 行くらい、中：200〜300 行くらい）。**計ってはいない**。

### E1. Sprite Renderer（カテゴリ Rendering2D）— 中

- Inspector：Texture（アセットのコンボ）・Color・Pixels Per Unit（64）・Pivot（足元に合わせるなら (0.5, 0)）・Flip X・コマ割り（横・縦の数）と今のコマ・Lighting（Unlit / Lit）・Alpha Cutoff・Order（同じ z で重なったときの順）。
- **Sprite Animation**（同じ Entity に付ける）：最初のコマ・コマ数・1 秒のコマ数・ループ。ゲームは「今どのアニメか」（最初のコマとコマ数）を変えるだけ。
- 描くのは**今ある `Renderer::DrawQuad3d`**（4 隅の位置と UV を渡す板）を使う → **新しいシェーダーは要らない**。左右反転とコマは UV の入れ替えだけ。
- `DefaultScene::Draw`（と `GameScene::Draw`）で `SpriteRenderSystem::Draw` を呼ぶ。

### E2. Body 2D（カテゴリ Physics）— 中

- Inspector：Gravity Scale・Use Gravity。**速度（velocity）はゲームが毎フレーム書く**。System が書く状態：`isGrounded`・`hitWallLeft/Right`・`hitCeiling`。
- 形は同じ Entity の **Collider（箱）**を使う。
- 「止まる相手」は、**Body 2D を持たない箱の Collider**（地面・壁・足場）。
- 動かし方（よくある、すり抜けにくいやり方）：**横に動かす → 重なった相手から横に押し戻す → 縦に動かす → 縦に押し戻す**。下に押し戻されたら接地。
- **Collider に `Is Trigger` を足す**：印を付けた Collider は止まる相手にならない（灯籠・光のかけら・ゴールの範囲・トゲ）。当たったことは今まで通り `GetHits` で分かる。
- 重力の強さは Settings の Project に "Physics" グループ。動くのは Play 中だけ。SYSTEM の後・ワールド行列の前に動かす（SYSTEM で決めた速度がそのフレームに効く）。
- 後で（今回は作らない）：下から通り抜けられる足場・動く足場・坂。

### E3. 移動ギズモ・Scene ビューでクリックして選ぶ — 中

- 選んでいる Entity に矢印（ImGuizmo。エンジンに入っている物）。W / E / R で移動・回転・拡大。
- **Ctrl を押しながら動かすと 0.5 ユニットずつ吸い付く**（マス目に並べやすい）。
- 動かした分は Undo できる（Inspector の変更と同じ履歴）。
- Scene ビューをクリック → その場所の Sprite / Collider の Entity を選ぶ。
- これが無くても作れる（Inspector に数字を打つ）が、ステージ作りの時間が大きく変わる。

### E4. シーンの設定：空を消す（SF4 の一部）— 小〜中

- Settings ウィンドウの **Scene** のページに「Sky（表示する・明るさ）」と「背景の色」。シーンファイルに `"settings"` として保存（SF4 の設計どおりの場所）。
- 空の画像を変える・IBL を作り直す所は、SF4 の本番で（2D では使わない）。
- **無い場合の代わり**：ゲームのシーンごとにクラスを書いて `SceneRenderer::GetSkybox()->SetIntensity(0.0f)`（GameScene と同じやり方）。

### E5. UI Image（カテゴリ Rendering2D）＋フェード — 小〜中

- UI Image：画面に貼る絵。位置（1280×720 の画面の中のピクセル、画面のどこを基準にするか）・大きさ・画像・色・順番。**タイトル画面・クリア画面をエディタで作れる**。
- フェード：`SceneManager::LoadScene("Result", 0.5f)`（暗くなる → 切り替わる → 明るくなる）。SF3 の設計どおり。画面いっぱいの黒い絵の濃さを変えるだけ。
- SF3 の Scene Change Component（コード無しの切り替え）は、時間が余ったら。案 A なら「ゴールに触れた」はゲームのコードで `LoadScene` を呼べば済む。

## 6. 20時間の使い方と予定

| 作業 | 時間 |
|---|---|
| エンジン E1〜E5 を写す・確かめる | 5〜6 |

### カレンダー（10/1 → 10/28）

| 期間 | やること | 終わりの目印 |

## 8. 気をつけること

- **提出の形を 2 週目に試す**：Release でビルド → exe と `resources/`・`MyEngine/`（シェーダー・エンジンの画像）・`Parameters/` を別のフォルダに写して、ダブルクリックで起動する。エンジンで作ったゲームは「作ったフォルダの外で動かない」ことが多いので、締め切り直前に気づくと危ない。
- **見つけたこと**：Release の exe は **`dxcompiler.dll` と `dxil.dll` が無いと起動しない**（シェーダーをコンパイルする DLL。検証で Release の exe が使う DLL の一覧を調べたら入っていた）。今はゲームのフォルダの一番上（`CG3_Project/`）に置いてあり、Visual Studio から起動すると作業フォルダがそこなので動く。**exe の隣にこの2つも入れる**（Debug はビルドの後に `x64/Debug/` へ写す設定があるが、Release には無い）。
- **エディタの物は製品版に入らない**：Release は ImGui を使わない（エディタ・Settings ウィンドウ・Project ウィンドウは無い）。調整した値は **Save してファイルにしてから** Release を作る。
- **ファイル名は英数字**：日本語の名前の画像・音は読めない。SceneFlow.md のパート K-3 の後は、Inspector の一覧に出ず、Console に警告が出る（名前を変えれば出る）。
- **素材の規約**：素材サイトの絵・音は、クレジットの書き方・加工してよいか・再配布（素材そのものを配る）を見る。`resources/CREDITS.txt` に「どこの・誰の・何を」を書いておく。
- **ブランチ**：エンジンは今の `feature/project-window` をコミット → develop へ（SceneFlow.md 13章の②のやり方）→ E1〜E5 は `feature/action-2d` で。ゲームは課題用に分けるなら、`CG3_Project` とは別のフォルダ（ゲームのプロジェクトを1つ作る）にするか、7章で相談。
