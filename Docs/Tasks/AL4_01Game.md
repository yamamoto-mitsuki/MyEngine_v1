## 1. ゲームの概要

**大きなトランポリンの上で、上から降ってくる図形に弾き出されないよう、何秒耐えられるかを競う1人用ゲーム。**

- 床はトランポリン。物が落ちると、そこを一番下にして床全体が V の字に沈み、**張りの強さで跳ね返して、物を上へ弾き返す**。
- 床は1枚でつながっている。**近くに重い図形が落ちると、自分の足元も一緒に沈み**（くぼみに向かって坂になる）、床が戻るときに**自分も跳ね上げられる**。
- 床が戻る（上に動いている）瞬間に合わせてジャンプすると、高く跳べる（トランポリンの「ダブルバウンス」）。
- 床の両端の外は穴。落ちたらゲームオーバー。
- スコア＝生き残った秒数。

## 2. 画面・カメラ

| 項目 | 内容 |
|---|---|
| スクロール | **しない（固定画面）**。床全体が1画面に収まる |
| カメラ | 少し斜め上から見下ろす角度で固定 |

| 床の端 | 両端を支柱で止める。支柱の外は穴 |

固定画面にする理由：
- 床全体の沈み方と跳ね返りが全部見えないと、「次にどこが跳ね上がるか」を読めない
- 落下予告の影が全部見える（画面外から急に落ちてこない）
- ステージを作らなくていい

## 3. ルール

### 勝ち負け
- 負け：床の両端の穴に落ちる（**これ1つだけ**）
- HPは無い。図形に当たっても吹き飛ぶだけ
- スコア：生き残った秒数

### 時間がたつと難しくなるもの
- 図形の重さ（重いほど深く沈め、周りを大きく跳ね上げる）
- 同時に落ちてくる数
- 床の柔らかさ（張りの強さ。弱いほど深く沈み、跳ね方が大きくなる）

### 落ちそうになる場面（ゲームの山場）
- 近くに重い図形が落ちる → 床がそこへ向かって沈み、坂で**くぼみに滑り寄せられる** → 床が戻るときに跳ね上げられ、図形にもぶつかりやすい
- 床が戻る勢いで高く跳ね上げられる → 空中で図形にぶつかる・着地点が穴の上になる
- 端の近く → 床が浅くしか沈まず、跳ね返りも弱い（落ち着ける場所だが、吹き飛ばされるとすぐ穴）
- 転がってくる・跳ねてくる図形に押される

## 4. 床（トランポリン）

- 中身は**横1列の、ピンと張った膜を点の並びで表した物**（65点）。両端の点は固定（支柱）。
- 1点ごとの動き：
  - 張りで、隣の点とまっすぐに並ぼうとする力（沈んだ所を引き上げる → **跳ね返す**）
  - 揺れが少しずつ収まるブレーキの力（減衰。強いほど跳ね返りが弱い）
  - 乗っている物（図形・プレイヤー）に押された力
- 物が落ちると、物は床を押し下げ（反作用）、床は張りで物を押し返す。**床が軽く張りが強いので、落ちた勢いがほとんどそのまま跳ね返りになる**。
- 確かめた数字（G1 の初期値。8m の高さから落とした場合）：

  | 落とした物 | 沈んだ深さ | 跳ね返った高さ |
  |---|---|---|
  | 60kg・真ん中 | 約1.1m | 約6.4m |
  | 60kg・端の近く（真ん中から7m） | 約0.7m | 約4.4m |
  | 200kg・真ん中 | 約2.5m | 約7.4m |
  | 60kg が止まっている4m横に 150kg | — | 止まっていた方が約4.5m 跳ね上がり、くぼみへ寄った |

- **エンジンの Elastic Surface Component**（Add Component → Physics → Elastic Surface）。乗れるのは **Rigidbody と Collider を付けた Entity**（プレイヤーも図形も同じ）。
- **当たり判定用はCPU**で計算する（GPUから読み戻すと遅れが出て面倒なため）。PhysicsSystem の小さな1歩（1/1200 秒）の中で、面と Rigidbody を一緒に進める。
- **厚みがある**（Thickness、初期値 0.3m）。上の面・下の面・手前と奥の壁・左右の端を描き、下の面も上の面と一緒に曲がる（分厚いゴムのマット）。当たるのは上の面だけ。両端に**支柱**（箱。Post Height・Post Width）。
- **見た目用はCS**で、上の1列をもとに奥行きのある面（格子）を作り、法線も計算する（→ 9章）。

## 5. 落ちてくる図形

### 種類（モデリングせず、エンジンの Primitive Renderer で描く）
図形1つ＝ **Rigidbody（重さ）＋ Collider ＋ Primitive Renderer** の Entity を **Prefab**（`resources/prefabs/`）にした物。球・箱は G1 でエンジンに入った。Cylinder・三角錐は G6 で Primitive Renderer に足す。出すのはゲームの `ShapeSpawner`（G2）。

| 形 | 役割（数字で差をつける） |
|---|---|
| 球 | 小さくて軽い。よく転がるが、耐久度は低い |
| Cylinder | 摩擦が小さい。転がり続けてプレイヤーを押してくる。横倒しで落ちると平らな面の縁で跳ね方が変わる |
| 立方体 | 標準。どっしり落ちて、沈み方も跳ね返りも普通 |
| 直方体 | 長い。床を広く押す。斜めに着地すると跳ね方が読みにくい |
| 三角錐 | 尖った角から刺さると床を深く沈め、大きく跳ね返す。不安定ですぐ倒れる |

- Ring は**却下**。物理は外側を円にすれば難しくないが、丸い形が3つ（球・Cylinder・Ring）になって役割が被るため。

### どこまで残るか（耐久度）
- **ぶつかった強さ（衝突したときの速さ）に応じて耐久度を減らす**。高い所から落ちた・重い図形は早く壊れる。
- 残りの耐久度は、ひびや色の変化で見せる。
- 耐久度が0になったら破片になって散る（破片はCSのパーティクル → 9章）。
- 端の穴に落ちたら、その場で消す。
- 同時に出す数に上限を付ける（例：6個）。超えたら一番古いものを壊す（保険）。
- トランポリンなので図形は何度も跳ねる。耐久度で消えるので、跳ね続けて溜まることはない。

### 落下の予告
- 落ちてくる図形の**影が床に落ちて、着地点を知らせる**（→ 8章）。

## 6. 図形の物理（3Dで回転する）

### 方針
- 位置は奥行き（Z）を0に固定。**回転は3Dで自由に回る**（前後にも傾く）。
- 当たり所（角・縁・面）によって、跳ね方・回り方が変わる。
- **エンジンの Rigidbody を広げて作る**（G6）。今の Rigidbody は回転しないので、角速度・慣性モーメントを足し、Collider の形の角の点ごとに面に押し返されるようにする。ほかのゲームでも「転がる箱」として使える。

### 床とのぶつかり方
図形の「角の点」それぞれについて調べる（G1 でエンジンに入れた `ElasticSurfaceSimulation::PushBack` を点ごとに使う。今は球の一番下・箱の底に並べた点）。

1. 点が床の高さより下に入ったら、その点を押し上げる力をかける
   - めり込んだ深さに比例するバネの力 ＋ 近づく速さに比例するブレーキ（ダンパー）
   - 向きは床に垂直（坂の上の物は、低い方＝くぼみの方へ押される）
2. その力は中心からずれた場所にかかるので、回転が生まれる
   - 回転の力（トルク）＝ `cross(r, F)`（`r`＝中心から点まで、`F`＝その点の力）
   - 角速度の変化＝トルク ÷ 慣性モーメント（x・y・z の3つの値）
3. 同じ力を逆向きに、床のその場所に加える（反作用）→ 床が沈み、張りで戻って図形を跳ね返す
4. 点の横向きの速さを打ち消す摩擦 → 転がる・止まる

| 形 | 調べる点 |
|---|---|
| 球 | 面に一番近い点（中心から、面に垂直な向きの逆へ半径の所）。G1 で入った |
| 立方体・直方体 | 角8個 |
| 三角錐 | 頂点4個 |
| Cylinder | 上下の縁の点（例：16個×2） |

- 床も図形も「バネの力」で計算するので、仕組みが1種類で済む。
- 床と図形は**同じ小さな1歩（1/1200 秒）ずつ一緒に進める**。1フレーム（1/60 秒）ごとにまとめて計算すると、突き抜ける・暴れる。
- 前後に暴れすぎたら、X・Y軸回りの回転だけ減速を強くして調整する。
- 角度はクォータニオン（エンジンにあるもの）で持つ。
- 図形同士の衝突は**最初は無し**。重なって見えて気になったら足す。

## 7. プレイヤー

### 床との関係
- プレイヤーも図形と同じく **Rigidbody＋Collider** を付けた Entity。エンジンが床に押し返すので、着地すると床が沈んで跳ね返される。何もしなければ、跳ねるたびに低くなって止まる。
- 床が坂になっていると、低い方（くぼみ）へ滑る（面に垂直な向きに押し返されるため。エンジンがやる）。
- ゲームの Script が書くのは操作だけ：地面にいるか（Rigidbody の `isGrounded`）・床が戻る勢い（`ElasticSurfaceSystem::GetVelocity`）を読んで、`velocity` を書く。ヒップドロップの一撃は `ElasticSurfaceSystem::AddImpulse`。

### アクション（3つだけ）

| 操作 | 内容 |
|---|---|
| 左右移動 | 地上では普通に動く。床が傾いていると滑る。空中では少しだけ動ける |
| ジャンプ（2段まで） | 1段目は足元の床が上に戻る勢いが上乗せされる（ダブルバウンス）。床が沈んでいる最中に跳ぶと低い。2段目は常に同じ高さ |
| ヒップドロップ | 空中で下。急降下して床を深く沈める。床が戻るとき、**自分も周りの図形も高く跳ね上がる**。近くの図形の耐久度を削る |

- ジャンプの回数は **着地したとき・硬直が解けたとき に2回に戻る**（統一）。

### 図形に当たったとき（硬直）（G4b で変えた。[G4Bounce.md](G4Bounce.md)）
- **飛ばされる向き・強さは物理**（Rigidbody 同士の押し合い＋跳ね返り Bounciness。重さ×速さ＝運動量が保たれる）。Script は速さを書かない。
- **硬直するのは、図形の勢い（重さ × こちらへ向かってきた速さ）が Stun Momentum（200 kg·m/s）以上のとき**。弱ければ、こちらが図形を弾き飛ばす。
- **図形の上には乗れる**（足元で当たったときは硬直しない）。
- 硬直中は操作できない（ヒップドロップもできない）。地上では摩擦で止まる。
- **硬直中も連続で当たる**（無敵にしない）。ハメ対策：連続で当たるたびに硬直時間を短くする（0.5 → 0.35 → 0.25 秒、下限あり。解けたら戻す）。**同じ図形からは 0.2 秒続けて当たらない**。

### 当たり判定
- **カプセル1つ**（横から見ると「円2つ＋線分」）。見た目のアニメに関係なく固定。
- エンジンの Collider に G3 でカプセルを足した（いつも立ったまま。Height は半球も入れた全体の高さ）。プレイヤーは半径 0.4・高さ 1.6。
- プレイヤーの Rigidbody は **Collide With Rigidbodies を付けたまま**（G4b。図形と押し合う・乗れる）。

### 見た目（レイマン型）
腕・脚が無く、**手足が体から離れて浮いている**人型。全部コードで作れる形で、障害物と被らないようにする。

| パーツ | 形 |
|---|---|
| 胴 | 楕円体（大きめ） |
| 頭 | 楕円体（胴の上。球と被らないよう少し縦長） |
| 手×2 | 小さな楕円体（胴の横に浮かせる） |
| 足×2 | 前後に長い楕円体（胴の下に浮かせる） |

- 色は白系にして、障害物には色を付ける（影がよく見え、見分けやすい）。
- 向きを変えるときは真横（90°）まで回さず、**60°くらいで止める**（少しカメラを向いて3Dらしく見える）。

### アニメーション（全部コードで動かす。骨のアニメは使わない）

| 状態 | 動き |
|---|---|
| 待機 | 胴を少し伸び縮み（呼吸）。手足をゆっくり上下 |
| 走り | 手足を sin 波で前後に振る（手と足は逆向き） |
| ジャンプ1段目 | 両手を上げる。体を縦に伸ばす |
| ジャンプ2段目 | 体全体を Z軸回りに1回転（前宙） |
| ヒップドロップ | 一瞬止まって丸まり（手足を体に寄せる）、まっすぐ下へ |
| 吹き飛び | 手足を大きく開き、飛ばされた方向に体を回す |
| 着地 | 体全体を一瞬横に潰して戻す（スクワッシュ＆ストレッチ）。床が沈む深さに合わせて潰すと、トランポリンらしく見える |

- 潰す・伸ばすは**一番上の親の拡大率**に掛ける。当たり判定は変えない。

## 8. 技術的挑戦①：影（シャドウマップ）

**今のエンジンには影が無い**（2026-10-19 時点。`RenderStates.h` に名前が出てくるだけ）。なのでエンジン側の作業になる。

- 平行光（太陽）1つのシャドウマップ。
- ゲームで使う場所：
  - **落ちてくる図形の影＝着地点の予告**（影がゲームに欠かせない）
  - 沈んだ床に影が落ち、床の形に沿って歪む
  - 白い体に図形や自分の手足の影が落ちる
- 固定画面なので、影を描く範囲（ライトから見た正射影の範囲）も固定でいい。

## 9. 技術的挑戦②：Compute Shader

CSの土台（CS-0）とCSスキニング（CS-1）はできている。

| 使う場所 | 内容 |
|---|---|
| **床の見た目** | CPUの1列の高さを受け取り、奥行きのある格子の頂点と法線をCSで計算する。奥行き方向にもたわみ（真ん中が深く、手前と奥の縁は浅い）を付けて、本物のトランポリンのような、すり鉢状に沈む面に見せる。G1 で CPU で作っている厚みのある板（`ElasticSurfaceSystem` の `DrawSlab`）を置き換える |
| **図形の破片** | 耐久度0で砕けた破片をGPUパーティクルにする。床の高さ（同じ1列のデータ）を読んで、床の上で跳ねさせる |

- 当たり判定に使うデータはCPU側にあり、GPUから読み戻さない。CSは見た目専用。
- **点を増やすのはここで（2026-10-20 にユーザーと決めた）**：見た目の格子は、CPU の点の間を CS で**なめらかに補間**（Catmull-Rom など）して、横にも細かくする。CPU の点（当たり用）は増やさない（増やすほど Steps Per Second を上げないと暴れて、重くなる。理由は [G3Player.md](G3Player.md) の 7.3・7.4）。

## 10. おおまかな作る順番

締切が近いので、**先に「遊べる最小限」を作り、影とCSを後から足す**。

| Step | エンジン | ゲーム | ここで分かること |
|---|---|---|---|
| G1 | **Elastic Surface**（弾む面・厚み・支柱）、Rigidbody の Mass と面との押し合い、**Primitive Renderer**（球・箱）（写経コード：[G1Trampoline.md](G1Trampoline.md)） | 試しに球を落とす Script | 沈んで跳ね返る・近くの物も跳ね上がる |
| G2 | **Prefab**、形の見た目（`PrimitiveMaterial`）、Model Renderer の Override（写経コード：[G2Prefab.md](G2Prefab.md)） | 図形を出す係（`ShapeSpawner`：Prefab を4種類まで・出やすさ・間隔） | 図形を増やせる形 |
| G3 | カプセルの Collider、`MoveTowards`（写経コード：[G3Player.md](G3Player.md)） | プレイヤーの操作（`PlayerController`：移動・2段ジャンプ・ヒップドロップ）・`Player.prefab`。見た目は仮 | 床の戻りに合わせたジャンプの手触り |
| G4 | 当たりの向き（`normal`・`CollisionInfo`）、Rigidbody 同士の押し合い（重さ・Collide With Rigidbodies）、`ColliderShape` の switch（写経コード：[G4Knockback.md](G4Knockback.md)） | 図形に当たったときの吹き飛び・硬直・連続ヒットの硬直短縮 | 落ちそうになる緊張感 |

| Text | **文字（Text Component）**・フォント（SDF・縁取り・影）・フォントの選ぶ欄（見本つき）（写経コード：[Text.md](Text.md)） | — | スコア・ゲームオーバーを出す準備 |
| G5 | — （Text はできた） | 耐久度・上限・穴で消す・スコア・ゲームオーバー | **ここで遊べる最小限が完成** |
| G6 | Rigidbody の回転・角の点での押し返し、Primitive Renderer に Cylinder・三角錐 | 図形の種類を増やす | 当たり所で跳ね方が変わる |
| G7 | 影（シャドウマップ） | 落下予告 | 技術的挑戦① |

| G9 | — | レイマン型の見た目とアニメ | 見た目の完成 |
| G10 | GPU パーティクル | 図形が壊れたときの破片 | 技術的挑戦②の追加 |

## 決めたこと

| 決めたこと | 理由 |
|---|---|
| **できるだけエンジン側で作る**（床・形・物理・影・CS はエンジン、ルールと操作はゲーム） | ユーザーの方針。ゲームを作りながら、ほかのゲームでも使えるエンジンの機能を増やす（0章） |
| 床はエンジンの Elastic Surface Component、乗る物は Rigidbody＋Collider | 部品を付けるだけで、プレイヤーも図形も床に乗って跳ねる。乗る物ごとにコードを書かなくてよい |
| 床に厚み（Thickness）と支柱を付ける | 紙のような1枚の面と線の支柱では、ゲームの画面として違和感があった。厚みは見た目だけ（当たるのは上の面） |
| 床は「波が広がる床」ではなく「**沈んで跳ね返るトランポリン**」 | ユーザーの希望（反発する、そのままのトランポリン）。最初の G1（重い床・遅い波）で 8m から落とすと 1.0m しか跳ね返らず、布や水面のようだった。軽い膜・強い張りにすると 6.4m 跳ね返る |
| 案A（トランポリン）で作る | 提出まで時間が少ない。ステージを作らなくていい |
| 障害物は積もらず、耐久度で消える | 積もって高くなると、トランポリンらしさが消えるため |
| 横スクロールしない | 床全体の沈み方・影の予告が全部見える。作る量が減る |
| 1人用 | 作る量を抑える |
| 負けは「穴に落ちる」だけ、HPなし | ルールを1つにして分かりやすくする |
| 図形は球・Cylinder・立方体・直方体・三角錐 | コードで作れる形だけ。Ring は役割が被るので却下 |
| 図形は3Dで回転、位置はZ=0に固定 | 3D表現として、当たり所で動きが変わるようにする |
| 床・図形・プレイヤーともにバネの力で押し返す | 仕組みが1種類で済む。正確な衝突計算より簡単。跳ね返りも同じ仕組みから自然に出る |
| 当たり判定はCPU、見た目はCS | GPUからの読み戻しは遅れが出て面倒 |
| アクションは移動・2段ジャンプ・ヒップドロップ | 少なく絞る。ヒップドロップで「攻め」もできる |
| 飛ばされるのは物理（跳ね返り）、硬直は「図形の勢いが強いとき」だけ・図形に乗れる・硬直中も当たる | ユーザーの希望（G4b）：乗れる方がいい・弱い図形は弾き飛ばせる方が面白い・Script より物理として正しい方がいい。ハメは硬直時間の短縮と同じ図形からの間隔で防ぐ |
| プレイヤーと図形は押し合う（Collide With Rigidbodies を付ける） | G4 ではすり抜けて Script が 6m/s で飛ばしていたが、付けても外しても違いが分からなかった（G4Bounce.md 1.1） |
| ジャンプは着地・硬直解除で2回に戻る | 統一した方が分かりやすい |
| プレイヤーはレイマン型（浮いた手足） | 関節が無くアニメが楽。潰す・伸ばすで弾む感じが出る |

- 重力の強さ（現実の 9.8 だとふわっとする。ゲームらしくキビキビさせるなら強める）
- 図形の出現パターン（ランダムの偏り、予告時間）
- タイトル・リザルト画面の内容
