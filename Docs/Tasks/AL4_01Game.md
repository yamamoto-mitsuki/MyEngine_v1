- 2026-10-22 に**企画を作り直した（3回目）**。参考にするゲームは **Jump Adventures**。氷のキューブを**左右移動とジャンプ（1回）だけ**で動かし、ギミックを使ってゴールの扉まで進む。

## 1. 課題の条件と、このゲームでの答え（⚠ 先生に確認する）

課題：**3D表現の2軸アクション。キャラクターを2次元の画面上でリアルタイムに操作し、移動・ジャンプ・攻撃・回避などのアクションで、敵や地形の障害を突破していくゲーム**。プレイ会は **10/28（水）第5回**。

| 条件 | このゲームでは | |
|---|---|---|
| 3D表現・2軸 | 3D の足場（押し出した多角形）と 3D の氷のキューブを横から見る。動きは X・Y だけ | ○ |
| 移動 | 左右 | ○ |
| ジャンプ | 1回。ギミック（水色の円・緑の壁・緑の円）で増える | ○ |
| 地形の障害を突破 | 熱湯・トゲ・風・穴・高い壁を、ギミックを使って越える | ○ |
| 回避 | 専用の操作は無い。トゲ・熱湯・風を、移動とジャンプでよける | △ |
| 攻撃・敵 | **無い** | × |

- **前の企画をやり直した理由が「攻撃・回避・敵が無い」だった**。今回もそこは同じなので、**「攻撃・敵が無くても、地形の障害を突破するゲームで条件を満たすか」を先生に確認する**。課題文は「攻撃・回避**など**」「敵**や**地形」なので、無くてもよい読み方もできる。
- もし「要る」と言われたら、**操作を増やさずに**足せる案（1日で入る大きさ）：
  - **踏んで倒せる敵「ひのこ」**：氷を溶かす火の玉。床を往復する。**上から踏むと消える（攻撃）**。横から当たると1ダメージ（ジャンプでよける＝回避）。氷と火なので世界観にも合う。
  - 「上から踏んだか」は、G4 で作った当たりの向き `normal` で分かる。エンジンの追加は要らない。

### 絵の作り
- 足場は**全部同じ岩のテクスチャ**で、**形だけ違う**（斜めの辺・台形・とがった形）。見えるのはほとんど前の面で、横の面が少し見える。
- 足場の**下の方は暗い**（穴の底が見えない）。
- 背景は**描いた絵**（夕焼けの空・山・針葉樹・海）。**何枚も重なっていて**、奥ほど**ぼけて**、**霧の色に溶ける**。

- 光る物（円・ばね・◆）は、光が周りに**にじむ**。

- 足場の上に草・トゲ。海辺には暗い紺の切り絵のような植物。
- キューブは半透明で、中に小さい箱が見える。森ではうす紫、海辺では白。HP が減ると**ひび**が入る。

## 4. ゲームの概要

**氷のキューブを左右移動とジャンプ（1回）だけで動かし、ギミックをつないで、ゴールの扉まで進む横スクロールのジャンプアクション。**

- 1つのレベルは短い（30秒〜1分）。扉に触れるとクリアして、次のレベルへ。
- ジャンプは1回。**水色の円・緑の壁・緑の円がジャンプを増やす**。これをつないで、熱湯・トゲ・風を越える。
- HP は 3。トゲで 1 減って、キューブに**ひび**が入る。熱湯に落ちると**一発で溶ける**。
- 場所（テーマ）は2つ：**山（森）**と**海辺**。

## 5. プレイヤー（氷のキューブ）

### 操作

| 操作 | キーボード | パッド | 内容 |
|---|---|---|---|
| 左右 | A・D / ←・→ | 左スティック・十字 | 地上は速く加速・減速、空中は少し弱く |
| ジャンプ | Space / W / ↑ | A | 1回。押した長さで高さが変わる |
| やり直し | R | Back | レベルの最初から |
| ポーズ | Esc | Start | つづける・やり直す・タイトルへ |

**跳ぶ手触りのための決まり**（横移動とジャンプだけのゲームなので、ここが一番大事。元のゲームに書いてなくても入れる）：
- **コヨーテタイム**：足場から歩いて落ちても、0.1 秒は地上のジャンプができる。
- **先行入力**：着地の 0.1 秒前に押したジャンプは、着地した瞬間に跳ぶ。
- **長押しで高さが変わる**：上がっている途中でジャンプを離すと、上向きの速さを半分にする。
- 落ちる時は重力を少し強く（ふわっとしない）。落ちる速さに上限。

### ジャンプの決まり

ジャンプは「**自分のジャンプ（1回）**」と「**水色の円のジャンプ**」の2種類。

| 自分のジャンプ | いつ |
|---|---|
| 戻る（1 にする） | 着地した・**緑の壁にくっついた**・**緑の円で吹っ飛んだ**（吹っ飛ばしたジャンプは数えない） |
| 使う（0 にする） | ジャンプした |
| 消える | 足場から歩いて落ちて、コヨーテタイム（0.1 秒）が過ぎた |
| 残る | 緑の壁・緑の円で戻った分は、使うか着地するまで残る |

| 水色の円のジャンプ | いつ |
|---|---|
| 使える | 体が円に触れていて、その円が「使える」 |
| 使うと | その円は「使った」になる。**円の中にいる間は、もう跳べない** |
| また使える | 体が円から**一度出たら**「使える」に戻る（入り直すと跳べる） |
| 円が2つ重なっている | 円ごとに覚える。使える方を1つ使う |

- 空中で両方使えるときは**円を先に使う**（自分のジャンプが残る方が遊びやすい）。
- 地上では自分のジャンプを使う。なので「地上から跳んで、円の中でもう一度」ができる。
- ジャンプの強さはどれも同じ（下向きの速さは消して、決まった上向きの速さにする）。
- 自分のジャンプは2つの値で持つ（G7）：**地面のジャンプ**（地面にいる間は満タン、足場から落ちたらコヨーテタイムで消える）と、**戻った自分のジャンプ**（緑の壁・緑の円で戻る。使うか着地するまで残る）。使う順番は「地面 → 円 → 戻った自分のジャンプ」（[G7Gimmick.md](G7Gimmick.md) の 1.2・1.3）。

### 状態

| 状態 | 重力 | 左右の入力 | ジャンプ | 次の状態へ |
|---|---|---|---|---|
| 移動（地上・空中） | あり | 地上の加速／空中の加速 | 緑の円の中：吹っ飛ぶ／地上：自分のジャンプ／空中：水色の円 → 自分の順 | 緑の壁に横から → 壁／緑の円の中でジャンプ → 吹っ飛び |
| 壁にくっつく | なし（止まる） | 壁から離れる向き → 空中（落ちる） | 壁ジャンプ（上＋壁と反対へ）。緑の円の中なら吹っ飛ぶ | → 空中 |
| 吹っ飛び | なし | 効かない | 別の緑の円の中：吹っ飛び直す（いつでも）／**始まって 0.3 秒はできない**。その後に押すと、吹っ飛びをやめてジャンプ | 何かにぶつかる・時間切れ（1.5 秒）→ 空中 |
| やられ | — | 効かない | — | 1 秒後にレベルの最初から |
| クリア | — | 効かない | — | 扉に吸い込まれて、次のレベル |

- `enum class` で持って、状態ごとの処理は `switch` で分ける（default は書かない）。
- 地上と空中は加速の強さ・使うジャンプが違うだけなので、同じ状態（Move）にした（G5）。地面にいるかは Rigidbody の `isGrounded` で見る。

### 当たり判定
- **球の Collider 1つ**（半径 0.5）。キューブは見た目だけ（子の Entity）。
  - 理由：多角形の足場との押し出しが簡単で確実（9章）。足場の角やつなぎ目で引っかからない。
  - 足場の端では、キューブが少しはみ出して見える。地面の向きに合わせてキューブを傾けるので、角から落ちる時も「転がり落ちる」ように見える。
- Rigidbody：重さ 1・Freeze Position Z・Collide With Rigidbodies を外す。足場の Physic Material は摩擦 0。
- **坂の上で止まれるようにする**。摩擦 0 だと坂を滑り落ちるので、地上では「坂に沿った速さ」だけにして、立っている間は重力を切り、足元へ少しだけ押し付ける（物理が押し戻して消す）。坂の向きは足場との当たりの `normal` から取る。坂に着地した瞬間は、空中の横の速さから始める（落ちてきた勢いで、ずり落ちないように）。（G6。[G6Polygon.md](G6Polygon.md) の 1.9）

### 見た目
- 外の箱（半透明の氷）＋中の小さい箱（色が濃い）。どちらも Primitive Renderer（子の Entity）。色はテーマで変える（山：うす紫、海辺：白）。
- **ひび**：HP 3 → ひび無し、2 → 小さいひび、1 → 大きいひび。最初は**テクスチャを3枚**用意して替える。P3 で氷のシェーダーにして、ひびを少しずつ広げる（10章）。
- 傾き（見た目だけ。当たりは回さない）：地上では地面の向きに合わせる。空中では進む向きへ少し傾く。風の中ではぐらぐら揺れる。吹っ飛び中はくるくる回る。
- ダメージ：白く光る・少し揺れる・「ピシッ」。やられ：トゲで HP 0 → **砕ける**（かけらが飛ぶ）、熱湯 → **溶ける**（縮んで湯気）。

### 初めの数値（触りながら決める。ImGui の Drag で変えられるようにする）

| 項目 | 値 |
|---|---|
| キューブの大きさ | 1m |
| 走る速さ | 7 m/s |
| 地上の加速・減速 | 60・70 m/s² |
| 空中の加速 | 35 m/s² |
| 重力 | 30 m/s²（Gravity Scale ≒ 3）。落ちる時は ×1.5 |
| ジャンプの高さ | 3m（上向きの速さ ≒ 13.4 m/s） |
| 落ちる速さの上限 | 20 m/s |
| コヨーテタイム・先行入力 | 0.1 秒・0.1 秒 |
| 長押しを離したとき | 上向きの速さ ×0.5 |

## 6. ギミック

| ギミック | 見た目 | 決まり | 作り |
|---|---|---|---|
| **水色の円**（ジャンプの円） | 水色の輪（目盛り付き・ゆっくり回る）＋真ん中に光る玉 | 円に触れている間、空中でもう一度跳べる。使ったら、円から一度出るまで使えない（5章） | 球の Trigger ＋ Sprite（Add）。使ったら輪が広がって消え、玉が暗くなる。出たら元に戻る |
| **緑の円**（吹っ飛ばす円） | 緑の輪＋矢印。矢印の向きに「> > > >」が並んで流れる | **輪の中でジャンプすると**、中心に寄ってから**矢印の向きにまっすぐ**飛ぶ（重力なし）。触れただけでは何も起きない。**始まって 0.3 秒はジャンプできない**。その後ジャンプすると、吹っ飛びをやめてジャンプする。**吹っ飛んだ後、1回だけジャンプできる**（G7b） | 球の Trigger。向きは Transform の Z の回転。「> > > >」はエンジンの **Arrow Strip**（子に置く。停止中も流れるので、Inspector で調整できる） |
| **緑の壁**（くっつく壁） | 足場と同じ作りで、明るい緑 | 空中で横から当たると**くっつく**（止まる）。**自分のジャンプが戻る**。ジャンプで「上＋壁と反対」へ跳ぶ。壁から離れる向きに入力すると落ちる。上に乗ったら普通の床 | Polygon Shape ＋ ゲームの `StickyWall`（印だけ） |
| **熱湯** | 半透明の青緑。湯気が上がる | 触れたら**一発アウト**（溶ける） | 箱の Trigger ＋ 半透明の箱（P3 で水のシェーダー） |
| **トゲ** | 白い三角が並ぶ | 触れると**1ダメージ**。触れたままなら減らない。**一度離れて、また触れたら**また1ダメージ | 箱の Trigger ＋ 三角の Sprite を長さの分だけ並べる |
| **風** | 範囲の中では、画面全体に白い線・葉が飛ぶ | 範囲の中では、風の向きに押される（強さが時々ゆれる）。上向きの風なら浮く | エンジンの `WindZoneComponent` ＋ 風の線（画面）＋葉のパーティクル |
| **ゴールの扉** | 光る扉 | 触れたらクリア | 箱の Trigger ＋ 扉の板（またはモデル） |
| **◆**（拾う粒） | 黄色く光る粒 | 触れたら拾う。右下の数が増える（クリアには要らない） | 球の Trigger ＋ Sprite（Add） |

### 決まりの細かい所
- **トゲ**：1列のトゲは**1つの Trigger** にする（1本ずつに分けると、歩くだけで何回も減る）。同じフレームに2つのトゲに触れても1ダメージ。当たったら少し上へはねる（はねる強さは 0 にもできる）。**無敵時間は無し**（「離れてから踏み直すとまた減る」を守るため）。
- **緑の円**：吹っ飛び中に別の緑の円の中でジャンプしたら、そっちの向きで吹っ飛び直す（つなげられる。0.3 秒の間でもできる）。吹っ飛びをやめるジャンプは、横の速さを半分残して、上向きは普通のジャンプの速さ。
  - ジャンプで発動（G7b）。輪の中では、地上でも空中でも、ほかのジャンプ（地面・水色の円・戻った自分のジャンプ）より先に吹っ飛ぶ。使った円は、出るまで使えない（水色の円と同じ。共通の `JumpRing`）。
  - ジャンプしてから 0.1 秒で線の始まり（ふつうは円の真ん中）に寄って飛ぶ（どこからでも、飛ぶ線が同じになる）。
  - G7c：子の Arrows（Arrow Strip）の**線に沿って**飛ぶ（曲げられる）。線の終わりの後は、終わりの向きへまっすぐ。LaunchOrb の End At Path End を付けると、線の終わりで吹っ飛びをやめて、その勢いのまま普通の空中へ。Arrows が無ければ、円の右（ローカルの +X）へまっすぐ。
  - 「何かにぶつかる」は、当たりの向きと飛ぶ向きが正面から約 60 度の内（内積 −0.5 未満）のとき。床をこすりながら横へ飛ぶだけなら止まらない（G7）。
- **緑の壁**：くっつくのは、当たりの `normal` が横向き（X の大きさが 0.5 より大きい）のとき（斜めの壁にもくっつく）。壁ジャンプした直後 0.2 秒は、同じ壁にくっつかない（押しっぱなしで戻ってくっつかないように）。吹っ飛び中に当たってもくっつく。
  - 壁から離れる向きに入力して離したときも 0.2 秒くっつかない。壁の方へ押しっぱなしだと、0.35 秒で戻って 2.7m 上にくっつく（同じ壁を登れる。G7 のテスト → まだ決めていないこと）。
- **ばね**：G7b でやめた（ユーザーの判断）。
- **風**：力は加速度（m/s²）。強さ ×（1 ＋ ゆれ）。画面の風の線は、範囲に入ったら 0.3 秒で出てきて、出たら 0.5 秒で消える。風の向きと強さは `WindZoneSystem::GetWindAt(位置)` で、プレイヤー・パーティクル・画面の効果が同じ値を読む。

### 元のゲームで確かめること（分からないので、今は上の決まりにしてある。数値1つで変えられるようにしておく）
- 緑の円の吹っ飛びは、まっすぐ（重力なし）か、放物線か
- 緑の壁のジャンプは、真上か、壁と反対へ斜めか
- 足場から歩いて落ちたとき、空中でジャンプできるか（今はコヨーテタイムの 0.1 秒だけ）
- トゲに当たったとき、はねるか
- 下に落ちたら一発アウトか（今はそうしている）

## 9. 形のエディタ（Polygon Shape）

### なぜ作るか
- 元のゲームの足場は、**同じテクスチャで形だけ違う**（斜め・台形・とがった岩）。
- Box を並べると角ばった階段になって、世界観が出ない。形ごとにモデルを作るのは時間がかかるし、数が増えると重い。
- このゲームは横から見る2軸なので、**横から見た形（多角形）が決まれば、足場は決まる**。
  - → **点を並べて多角形を描くと、奥へ押し出した 3D の足場になる**仕組みを作る。**当たり判定も同じ点から作る**。
  - 横から見るゲームなら何にでも使えるので、エンジンの機能にする。

### 作る物（エンジン）

| 物 | 中身 |
|---|---|
| `PolygonShapeComponent`（Polygon Shape） | 形。外周の点（ローカルの XY、最大 32 点）と奥行き。Component は memcpy できる型でないといけないので、点は `std::array` ＋点の数で持つ |
| `PolygonRendererComponent`（Polygon Renderer） | 見た目。`PrimitiveMaterial`（色・テクスチャ・陰の付け方）を使い回す。**UV をワールド座標で作る**・テクスチャ1枚の大きさ（m）・横の面の暗さ |
| `PolygonShapeSystem` | 2つの Component の登録と、形からメッシュを作って描く。**形が変わった時だけ**作り直す（G6 で、形と見た目の System を1つにした） |
| `ColliderShape::Polygon` | 当たり。同じ Entity の Polygon Shape の点を使う |
| 形の編集（Scene ビュー） | 点をドラッグ・足す・消す。Undo できる |
| Create メニュー | Hierarchy の「＋」→ 3D Object → Polygon（四角の足場。Shape・Renderer・Collider 付き） |

- Polygon Shape・Polygon Renderer・Collider の3つに分ける（Unity の MeshFilter・MeshRenderer・MeshCollider と同じ考え）。形は1か所にだけ持つ。
- 当たりの無い飾り（前景のシルエットなど）は、Collider を付けなければいい。
- Entity の回転は Z だけ使う（X・Y で回すと、見た目は回るが当たりは回らない。Inspector の Point Count の説明に書いた）。

### メッシュの作り方
- **前の面**：多角形を三角形に分ける。**耳切り法（Ear Clipping）**：多角形から「耳」（となりの2点と結んだ三角形の中に、ほかの点が入っていない角）を1つずつ切り取っていくと、全部三角形になる。へこんだ形もできる。点が 32 個までなので、遅い方法（点の数の3乗くらい）で十分。点が時計回りに並んでいたら、反時計回りに並べ直してから分ける。
- **横の面**：辺ごとに四角を1枚（法線は外向き）。少し暗くして、形が分かるようにする。
- **後ろの面**：カメラから見えないので作らない。
- **UV**：前の面は「ワールドの XY ÷ テクスチャ1枚の大きさ」。横の面は「辺に沿った長さ, Z」。だから**足場を動かしても伸ばしても、テクスチャは伸びず、隣の足場とつながる**（元のゲームの「同じテクスチャで形だけ違う」）。
- 最初は Elastic Surface と同じく、`Renderer::DrawMesh` に毎フレーム渡す（作ったメッシュは覚えておき、写して渡す）。足場が増えて重くなったら、GPU に置きっぱなしのメッシュにする。

### 当たり判定
- **球 × 多角形**：球の中心が多角形の中か（内外判定：中心から横へ線を伸ばして、辺と交わる回数が奇数なら中）と、一番近い辺の上の点を調べて、押し出す。
  - **へこんだ形も、三角形に分けずにそのまま**扱える。三角形に分けて判定すると、分けた所の辺（本当は無い辺）で引っかかる。
- Z は「奥行きの中に入っているか」だけ見る。押し出すのは X・Y だけ。
- 箱 × 多角形・多角形 × 多角形は、今回は作らない（プレイヤーは球。ギミックの Trigger は足場と当たる必要が無い）。来たら「当たらない」として扱い、Inspector の説明に書く。カプセルは今までどおり「線分の上の一番近い球」に置き換わるので、当たる（G6）。
- `CollisionSystem::CalcPushOut` の switch に Polygon を足す。重なりの判定・当たりの向き・Rigidbody の押し戻しが全部これを使うので、1か所で済む。
- Collider の線（ギズモ）は、前の面と後ろの面の外周を描く。

### Scene ビューでの編集

| 操作 | 内容 |
|---|---|
| Inspector の **Edit Shape** ボタン | 形の編集を始める・終わる（Unity の Edit Collider と同じ）。編集中は移動のギズモを隠す |
| 点（■）をドラッグ | 動かす。**グリッド（0.25m）に吸い付く**。Ctrl を押している間は吸い付かない |
| 辺の真ん中の **＋** をクリック | そこに点を足す |
| 点をクリックして Delete | 消す（3点より少なくはできない） |
| Ctrl+Z / Ctrl+Y | 戻す・やり直す。ドラッグ1回で1つ（`EditorHistory::RecordComponentChange`。Component が memcpy できる型なので、前と後をそのまま覚えられる） |
| 形がおかしい時 | 辺が交差したら線を赤くして、三角形に分けない（描かない） |
| Inspector | 点の一覧（Drag で数値を直せる）・奥行き。「中心を原点へ」ボタンは作らなかった（Transform も一緒に動かすことになり、1件の履歴にできないので） |

- 点は「その足場の前の面（見えている面）」の上で動かす（マウスのレイと平面の交点。Scene ビューのクリックで選ぶ所と同じく `Camera::ScreenPointToRay` を使う）。
  - `ScenePicking.h` のコメントは `ScreenPositionToRay` と書いてあったが、本当の名前は `ScreenPointToRay`。G6 で直した。
- Scene ビューのカメラを**正面（-Z 側から）に向けるボタン**は作らなかった（右上の軸の −Z を押せば正面になる）。

## 10. 見た目（世界観）

### 奥行きの並び（カメラは -Z から +Z を見る。傾けない）

```
カメラ      z = -17     FOV 40°（画面の高さに 12m くらい入る）
前景        z = -4〜-8  手前の岩・草のシルエット            … 手前がぼける
遊ぶ面      z = 0       足場（奥行き -2〜+2）・キューブ・ギミック … ピントが合う
近い背景    z = +8〜+15 木                                  … 少しぼける・少し霧
中の背景    z = +25〜+40 木の列・岩                         … ぼける・霧
遠い背景    z = +80     山                                  … 強くぼける・ほぼ霧の色
空          一番奥       夕焼けのグラデーションの絵
```

- 背景は全部 **Sprite Renderer の板**（AI で描いた透明 PNG）。カメラが透視なので、**遠い板ほどゆっくり動いて（パララックス）**、何もしなくても奥行きが出る。遠い板ほど大きくする。
- 背景の板は **Alpha Clip**（奥行きを書く）にする。DOF とフォグは奥行きを使うので、半透明のまま描くと、後ろの空の奥行きでぼけてしまう。霧のもやの板だけは半透明でいい。

### カメラ（G5 の `CameraFollowComponent`）
- キューブをなめらかに追う（少し遅れて付いてくる。走っている間は「速さ × Smooth Time」くらい遅れる）。
- **遊び**：キューブが真ん中から少し動いただけでは動かない（ジャンプのたびに画面が上下しないように）。
- **地面にいる間は縦を合わせる（Ground Snap Y）**：遊びだけだと、跳んだ後にカメラが上にずれたまま戻らなかった（G5 のテスト）。跳んでいる間は遊び、着地したら合わせる。
- 追い方（Mode）を選べる。初めは **Look Ahead**：速さ × 0.4 秒だけ先を見せる（7m/s で 2.8m。止まると真ん中に戻る。縦は先読みしない。上限 3m）。先読みも指数補間で変える。
- レベルの端（Camera Follow の Bounds）で止まる。
- 吹っ飛びのような速い動きでも、キューブが画面から出ないように、遅れの上限を決める。

### 元のゲームの見た目と、作り方

| 見た目 | 作り方 | Step |
|---|---|---|
| 足場：同じ岩のテクスチャで、形だけ違う | Polygon Shape ＋ ワールド座標の UV | G6 |
| 足場の下ほど暗い・穴の底が見えない | **高さの霧**（低い所ほど暗い色が濃くなる） | G10 |
| 奥ほど霧の色（青緑・青灰）に溶ける | **距離の霧**（ピントの面より奥から効き始める） | G10 |
| 奥と手前がぼける | **被写界深度（DOF）**。ピントは遊ぶ面（z = 0） | G11 |
| 光る物のにじみ | Bloom（ある）。円・◆ は Add の Sprite で明るく | G7 |
| 画面の端が暗い | Lens の Vignette（ある） | G10 で調整 |
| 夕焼けの色・海辺の青灰 | テーマごとに：平行光の色・環境光・霧の色2つ・背景の絵 | G10 |
| 風：画面全体に白い線 | **風の線**。Lens のパスに足す（最後に画面全体へ重ねる効果なので）。強さと向きはゲームが毎フレーム書く（今の `addRadialBlur` と同じ形） | G8 |
| 風：葉が飛ぶ | パーティクル（AccelerationField で風の向きへ） | G8 |
| 草・トゲ・シルエットの植物 | 透明 PNG の Sprite（Alpha Clip）。Prefab にして手で置く | G10 |
| 半透明の氷・中の箱 | 外の箱（半透明）＋中の箱 → P3 で屈折する氷のシェーダー | G5 / G12 |
| 熱湯 | 半透明の箱＋湯気 → P3 で揺れる・奥が歪む水のシェーダー | G8 / G12 |

- **影（シャドウマップ）は後回し**。横からまっすぐ見るので、足場の上の面がほとんど見えず、影もほとんど見えない。

### 霧（フォグ）の中身（G10）
- 全部の 3D のシェーダー（モデル・Primitive・Polygon・Sprite の板・パーティクル）の最後で、色に霧を混ぜる。共通の関数 `ApplyFog` を `Fog.hlsli` に1つ作る。
- 値は**カメラの定数バッファ（b0）に足す**。モデルの PS はもう鏡面反射のためにカメラの位置を読んでいるので、同じ所に足せば届く（読んでいない PS は include を足す）。ルートシグネチャを変えずに済み、Scene ビューだけ霧を切ることもできる。
- **距離の霧**：`1 − exp(−濃さ × (カメラからの距離 − 始まり))`。始まりはピントの面より少し奥（遊ぶ面ははっきり見える）。色は明るい（青緑・青灰）。
- **高さの霧**：`exp(−(高さ − 基準の高さ) × 減り方)`。色は暗い（穴の底を暗くする）。
- 値はシーンに置く `FogComponent`（エンジン。1シーンに1つ）に持たせる → レベル・テーマごとに変えられる。

### 被写界深度（DOF）の中身（G11、技術的挑戦）
「ぼかし」の正体はこれ。カメラのピントが合っていない所（奥・手前）がぼける効果。
1. 深度を読めるようにする。今の深度は `D24_UNORM_S8_UINT` で、シェーダーから読めない → `R32_TYPELESS` で作り、DSV は `D32_FLOAT`、SRV は `R32_FLOAT` にする。
2. 深度 → **ボケの大きさ（CoC：Circle of Confusion）**。ピントの面からの距離で、手前ボケ・奥ボケ。
3. 半分の大きさに縮めて、**Compute Shader でぼかす**（横・縦の2回。一列を groupshared メモリに読み込んでから足す）。
4. 元の絵とぼけた絵を、CoC で混ぜる。
- ピントの合ったキューブが、ぼけた背景ににじまないように、足すときの重みを「その点のボケの大きさ」で決める。
- 手前のボケが、ピントの合った物の上にはみ出す処理は P3。
- 値（ピントの Z・ピントの幅・最大のボケ）は Settings の PostEffect（Bloom・Lens と同じ所）。Scene ビューでは切れるようにする。

## 11. 技術的挑戦

前の企画では「影」と「CS」だった。このゲームの見た目の中心は**ぼかしと霧**なので、こう変えたい（→ まだ決めていないこと）。

| | 内容 | 学べること |
|---|---|---|
| ① 被写界深度（DOF）＋フォグ | 深度から CoC を出してぼかす。霧を全部のシェーダーに入れる | ポストエフェクトで深度を使う・深度を距離に直す・シェーダーの共通化 |
| ② Compute Shader | DOF のぼかしを CS で（groupshared）。P3 で GPU パーティクル（葉・湯気・氷のかけら） | CS-0（土台）・CS-1（スキニング）の次に、画像処理と粒の更新 |
| （③ 余裕があれば）屈折 | 不透明な物を描いた後の画面を写して、氷・熱湯の奥を歪める | 描く順番・画面のコピー |

- グラフィックのロードマップ（ShadowMap → トゥーン → …）のうち、「5 ステージの空気（フォグ・DOF）」を先にやる形になる。このゲームの絵に一番効くので。

## 決めたこと

| 決めたこと | 理由 |
|---|---|
| 企画を作り直す（3回目）。参考は Jump Adventures | ユーザーが作りたいゲームを決めた |
| 操作は左右移動とジャンプ（1回）だけ | 元のゲームと同じ |
| ジャンプは「自分の1回」＋「水色の円」。緑の壁・緑の円で自分のジャンプが戻る | ユーザーの説明 |
| 空中では円を先に使う | 自分のジャンプが残る方が遊びやすい |
| コヨーテタイム・先行入力・長押しの高さを入れる | 横移動とジャンプだけのゲームは、跳ぶ手触りがすべて |
| プレイヤーの当たりは球、キューブは見た目だけ | 多角形との押し出しが簡単で確実。角・つなぎ目で引っかからない |
| 足場は Polygon Shape（多角形を奥へ押し出す）＋形のエディタ | Box では世界観が出ない。モデルを増やすと重い。横から見るので外形だけで足りる |
| テクスチャはワールド座標の UV | 足場を伸ばしても伸びず、隣とつながる |
| 多角形の当たりは、三角形に分けずに辺と内外判定で | 分けるとつなぎ目の辺で引っかかる。へこんだ形もそのまま扱える |
| トゲは1列＝1つの Trigger、無敵時間なし | 「離れてから踏み直すとまた減る」を守る |
| 熱湯・下に落ちる＝一発アウト。やられたらレベルの最初から | 1レベルが短いので中間地点は要らない |
| 場所は山（森）と海辺の2つ、6レベル | ユーザーの説明。1レベルに新しい物を1つ |
| 背景は板（Sprite）を奥行きに並べる | 透視カメラでパララックスが勝手に出る。モデルより軽い |
| 世界観の中心はフォグと DOF。影は後回し | 元のゲームの絵の中心。横からまっすぐ見ると影はほぼ見えない |
| フォグの値はカメラの定数バッファに | 3D のシェーダーにはもう入っているので、ルートシグネチャを変えずに済む |
| DOF のぼかしは CS | 技術的挑戦②（CS）とつなげる |
| P1 を 10/25 までに | 残り6日。遊べる形を先に |
| ばねはやめる（G7b） | ユーザーの判断（遊びとして微妙） |
| 緑の円は、輪の中でジャンプしたら発動。吹っ飛んだ後に1回跳べる（G7b） | ユーザーの判断。触れただけで飛ぶより、自分のタイミングで飛べる |
| 向きを示す「> > > >」はエンジンの Arrow Strip | Script は停止中に動かないので、エディタで見ながら調整できない。コンベア・風などにも使える |
| 矢印は曲げられて、緑の円はその線に沿って飛ぶ（G7c） | ユーザーの判断。曲線は点を通る Catmull-Rom（Polygon Shape と同じ点の編集）。見た目と飛び方がいつもそろう |
